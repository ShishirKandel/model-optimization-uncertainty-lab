# Model lab

An interactive companion to STW7085CEM Advanced Machine Learning coursework by Shishir Kandel, Netra Bahadur Budhathoki Magar and Rijwol Shakya. Website companion published by Shishir Kandel.

**Live website:** https://ShishirKandel.github.io/model-optimization-uncertainty-lab/

## Explore

- **Lake forecasts:** browse 478 Nepal lakes from the sealed 2024 evaluation, compare five regression models with nominal 90% prediction intervals, and inspect three separately labelled expansion classifiers. Filter by basin or lake ID; download an individual record.
- **Room controller:** adjust temperature error and outdoor temperature, try presets or a manual override, and inspect the manual Mamdani controller's command, output aggregation and active rules.
- **About & evidence:** meet the research team in author order, examine provenance and download the exported lake dataset. The combined written report is submitted separately and is not published here.

The lake predictions are saved experimental outputs, not a live forecasting service. Lake-area change is not flood risk. The live fuzzy controller is the manual baseline, not the GA-optimised variant, and is not connected to equipment. The report distinguishes synthetic-policy fit from actual room tracking.

## Run locally

Requires Node.js 20 or newer. No dependencies are needed to serve the website:

```sh
npm start
```

Open http://127.0.0.1:4173. Use an HTTP server rather than double-clicking `index.html`, because the ES modules and JSON data are loaded through the browser.

## Verify

The portable controller test uses 231 frozen reference cases generated by the existing Python `safe_control` entry point. It checks commands, rule activations, output aggregation, invalid sensors, clipping, override precedence and repeated-call independence.

```sh
npm test
```

Browser interaction tests require Google Chrome:

```sh
npm ci
npm run test:browser
```

The browser tests start the local server automatically. Set `TEST_BASE_URL` to a deployed site to run them against that site.

## Data and reproduction

`data/lakes.json` includes source-file SHA-256 hashes and the evaluated run identity. Areas are km²; change, interval endpoints and probability are fractions. Stored regression log ratios were converted with `expm1`. The metric named `pr_auc` in the source is average precision. No training or finalisation is performed by this site.

The inventory is attributed to Rawlins et al., version 1.02, [Zenodo DOI 10.5281/zenodo.19370146](https://doi.org/10.5281/zenodo.19370146), licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). This website exports the evaluated subset and adds derived model outputs and metrics. Attribution is also included in the data and website.

`tools/export_lakes.py`, `tools/export_controller.py` and `tests/test_export_lakes.py` are coursework-workspace tools: they require this repository to be located as `website/` under the original coursework directory with the original `src/`, `configs/` and data/artifact files. They do not run from a standalone clone. In that workspace:

```sh
python website/tools/export_lakes.py
python website/tools/export_controller.py
python -m unittest discover -s website/tests -p test_export_lakes.py -v
```

The exported JSON and controller reference fixtures are bundled, so the published website and `npm test` work without the original workspace. The existing [Task 1 source repository](https://github.com/ShishirKandel/model-optimization-uncertainty-task-1) is a convenience copy; the original experiment's archived snapshot remains the reproduction authority.
